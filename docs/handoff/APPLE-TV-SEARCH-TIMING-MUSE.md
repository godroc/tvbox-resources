# GG Apple TV：搜索耗时交接

## 本轮交付

只更新 Apple TV 预览，稳定入口、原生搜索、直播和私密模块不变。补丁针对 Apple TV 预览的 `app.js`，不是旧版 RC119 通用补丁。保留线上入口与缓存版本，并在安装前备份入口和被替换的文件。

页面内 `GGApp.searchTiming()` 返回三项毫秒数据：

- `firstCardMs`：从提交关键词到第一张结果卡片创建，不等于浏览器首帧绘制。
- `firstValidCardMs`：首次在结果卡片上观察到检测状态为有效，可能包含缓存命中，不代表已验证起播。
- `lastCheckBatchMs`：检测队列最近一批的耗时，用于辅助定位；不是本次搜索的累计耗时，也可能来自上一批。

未观察到的里程碑返回 null。数据仅保存在当前页面内存，不上传关键词或分享地址，不改变搜索、检测或筛选策略。

## 接手顺序

1. 在同一台电视或模拟器，用相同配置和来源搜索同一个片名三次。分别记录冷启动和回访，区分「隐藏失效」和「仅有效」。记下首卡、首条有效、前 20 条可见所需时间；前 20 条目前需要人工计时。
2. 对比 MiniPC 与 Oracle 的首批响应及检测耗时。若首卡慢，先拆后端源响应、WebHome 接收与渲染；若首条有效明显晚，先看检测队列、缓存来源及状态过滤。没有同条件计时前不要改并发。
3. 复现绿点却被取消分享，用单资源强制刷新复核。分别记录服务缓存、本机缓存和现场状态；不把分享有效等同起播成功。
4. 继续回归：搜索结果海报 → 原生播放背景 → 返回后的继续观看；同一份配置下读取选集诊断，对照播放器按钮。未证实字段前不要扩大文件名猜测。
5. 用遥控器验收主页到精选、收藏、详情、剧照、资源和播放返回；确认浅色背景上的文字可读。首页精选的继续播放露出按用户意见暂缓调整。
6. 真机验收后再决定是否推广到稳定版。使用独立提交、备份与缓存版本，保留回退入口。切勿把局域网配置、历史字段原值或账号信息放进公开仓库。
